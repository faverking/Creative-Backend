# 工程目录与运行指南

## 1. 项目定位

本项目是基于 `NestJS + MongoDB + JWT/OAuth` 的内容平台后端，当前稳定能力包括：

- 用户认证、会话与 OAuth 登录
- 四类内容业务：情报、游戏、书库、图包
- 评论、收藏、草稿、通知、历史记录
- 首页聚合、精选推荐、快速搜索、全文检索、相关推荐
- 管理端精选配置、内容治理、AI 编辑辅助
- 本地媒体上传、预览、下载与 ZIP 打包

## 2. 目录结构

```text
src/
├─ main.ts
├─ app.module.ts
├─ admin/                  # 管理端内容治理与汇总
├─ ai/                     # 管理端 AI 编辑辅助
├─ articles/               # 情报
├─ auth/                   # 登录、刷新、OAuth、授权
├─ books/                  # 书库
├─ comments/               # 评论与回复
├─ common/                 # 守卫、装饰器、公共常量与工具
├─ config/                 # registerAs 配置与环境校验
├─ drafts/                 # 草稿
├─ favorites/              # 收藏
├─ featured-contents/      # 精选配置
├─ history/                # 浏览历史
├─ home/                   # 首页聚合
├─ images/                 # 图包
├─ infra/
│  ├─ audit/
│  ├─ database/
│  ├─ logger/
│  ├─ mail/
│  ├─ metrics/
│  ├─ redis/
│  └─ storage/
├─ interactions/           # 收藏/评论计数与关系校验
├─ media/                  # 媒体上传、预览、下载
├─ notification/           # 消息通知
├─ report/                 # 预留报表域
├─ search/                 # 搜索、精选、相关推荐
├─ topics/                 # 游戏
├─ types/                  # 类型聚合与共享定义
├─ users/                  # 用户资料与业务统计
└─ workspace/              # 跨内容摘要、关系清理、访问记录
```

说明：

- 当前仓库采用模块化单体组织方式。
- 主要分层遵循 `controller -> service/application -> repository -> schema`。
- `workspace/` 是内部跨域能力，不直接暴露独立 HTTP 控制器。
- `types/` 主要用于共享类型聚合，不是独立业务模块。

## 6. 索引同步

一次性同步索引：

```bash
pnpm db:indexes:sync
```

用途：

- 将当前 schema 定义的索引同步到已有数据库
- 补齐新增 partial index
- 清理已经移除的旧索引

启动时自动同步：

```env
MONGO_SYNC_INDEXES_ON_BOOT=true
```

说明：

- 默认关闭
- 建议只在开发环境或维护窗口使用
- 生产环境更推荐显式执行 `pnpm db:indexes:sync`

## 7. 运行说明

### 7.1 API 基础前缀

- 默认：`http://localhost:3000/api/v1`

### 7.2 关键入口

- 首页主体：`GET /api/v1/home`
- 精选推荐：`GET /api/v1/search/featured`
- 全文搜索：`GET /api/v1/search/fulltext`
- 快速搜索：`GET /api/v1/search/quick`
- 相关推荐：
  - `GET /api/v1/articles/:id/related`
  - `GET /api/v1/books/:id/related`
  - `GET /api/v1/topics/:id/related`
  - `GET /api/v1/images/:id/related`
- 管理员精选：`GET /api/v1/admin/featured-contents`
- 管理端内容治理：
  - `GET /api/v1/admin/content/summary`
  - `GET /api/v1/admin/content`
- 管理端 AI 编辑辅助：
  - `POST /api/v1/admin/ai/compose`
  - `POST /api/v1/admin/ai/compose/stream`

### 7.3 当前默认业务规则

- 四类内容提交后默认写入公开态与已审核态
- 公开接口统一只返回可公开内容
- 图包业务已移除 `width`、`height`
- 书籍业务已移除旧字段 `hots`
- 游戏业务已移除旧字段 `scheduleLabel`
- AI 编辑辅助只返回建议，不直接写业务内容库

## 10. 阿里云非 Docker 部署

### 10.1 服务器环境

建议准备：

- Node.js `>=20`
- pnpm `10.11.0`
- MongoDB
- Redis 可选
- 可持久化的媒体目录，例如 `/var/lib/mononest/media`

### 10.2 生产环境变量

在服务器项目根目录创建 `.env`，不要使用本机 `.env.local`。

模板文件：

```bash
deploy/env.production.example
```

必须替换的变量：

- `CORS_ORIGINS`
- `MONGO_URI`
- `JWT_ACCESS_SECRET`
- `JWT_REFRESH_SECRET`
- `OPENAI_API_KEY`
- `MEDIA_STORAGE_ROOT`

按需启用的变量：

- `REDIS_ENABLED`
- `REDIS_URL`
- `AUTH_ENABLE_OAUTH`
- `OAUTH_GOOGLE_CLIENT_ID`
- `OAUTH_GOOGLE_CLIENT_SECRET`
- `OAUTH_GOOGLE_REDIRECT_URI`

### 10.3 启动命令

安装依赖：

```bash
pnpm install
```

构建：

```bash
pnpm build
```

启动：

```bash
pnpm start:prod
```

### 10.4 上线前检查

- `.env` 中 `NODE_ENV=production`
- `CORS_ORIGINS` 只配置真实前端域名
- `JWT_ACCESS_SECRET` 和 `JWT_REFRESH_SECRET` 不能使用示例值
- `MEDIA_STORAGE_ROOT` 指向服务器持久化目录
- 服务器安全组放行后端端口或反向代理端口
- 若使用 OpenAI，确认服务器能访问 `OPENAI_BASE_URL`
- 首次部署或 schema 变更后，维护窗口执行 `pnpm db:indexes:sync`

## 12. 常见排查

### 12.1 `pnpm` 不可用

```bash
corepack enable
corepack prepare pnpm@10.11.0 --activate
pnpm -v
```

### 12.2 Mongo 无法连接

优先检查：

- `MONGO_URI`
- `MONGO_DB_NAME`
- Mongo 服务是否启动

### 12.3 索引没有生效

优先检查：

- 是否执行过 `pnpm db:indexes:sync`
- 是否开启了 `MONGO_SYNC_INDEXES_ON_BOOT`
- 数据库里是否残留旧索引

### 12.4 媒体上传失败

优先检查：

- 媒体大小限制
- 上传字段名是否正确
- `MEDIA_STORAGE_ROOT` 是否可写

### 12.5 OAuth 回调失败

优先检查：

- `AUTH_ENABLE_OAUTH`
- Google client 配置
- redirect URI 是否一致

### 12.6 AI 接口不可用

优先检查：

- `OPENAI_API_KEY`
- `OPENAI_MODEL_ADMIN_COMPOSE`
- `AI_ADMIN_STREAM_ENABLED`
- OpenAI 上游网络是否可达
- 调用用户是否已登录
