# 工程目录与运行指南

## 1. 项目定位

`MonoNest` 是基于 `NestJS + MongoDB + JWT/OAuth` 的内容平台后端，当前稳定能力包括：

- 用户认证、会话与 OAuth 登录
- 四类内容业务：情报、游戏、书库、图包
- 评论、收藏、草稿、通知、历史记录
- 首页聚合、精选推荐、快速搜索、全文检索、相关推荐
- 管理端精选配置、内容治理、AI 编辑辅助
- 本地媒体上传、预览、下载与 ZIP 打包
- 生产健康检查与 PM2 日志切割

生产部署唯一主路径为：

```text
push main -> GitHub Actions 构建 -> 上传阿里云 -> release 目录解压 -> PM2 启动当前 release
```

## 2. 目录结构

```text
src/
├─ main.ts
├─ app.module.ts
├─ admin/                  # 管理端内容治理与汇总
├─ ai/                     # 管理端 AI 编辑辅助
├─ articles/               # 情报
├─ auth/                   # 登录、刷新、OAuth、授权
├─ books/                  # 书库
├─ comments/               # 评论与回复
├─ common/                 # 守卫、装饰器、公共常量与工具
├─ config/                 # registerAs 配置与环境校验
├─ drafts/                 # 草稿
├─ favorites/              # 收藏
├─ featured-contents/      # 精选配置
├─ history/                # 浏览历史
├─ home/                   # 首页聚合
├─ images/                 # 图包
├─ infra/
│  ├─ audit/
│  ├─ database/
│  ├─ logger/
│  ├─ mail/
│  ├─ metrics/
│  ├─ redis/
│  └─ storage/
├─ interactions/           # 收藏/评论计数与关系校验
├─ media/                  # 媒体上传、预览、下载
├─ notification/           # 消息通知
├─ report/                 # 预留报表域
├─ search/                 # 搜索、精选、相关推荐
├─ topics/                 # 游戏
├─ types/                  # 类型聚合与共享定义
├─ users/                  # 用户资料与业务统计
└─ workspace/              # 跨内容摘要、关系清理、访问记录
```

说明：

- 当前仓库采用模块化单体组织方式。
- 主要分层遵循 `controller -> service/application -> repository -> schema`。
- `workspace/` 是内部跨域能力，不直接暴露独立 HTTP 控制器。
- `types/` 主要用于共享类型聚合，不是独立业务模块。

## 3. 运行环境

基础要求：

- Node.js `>=20`
- pnpm `10.11.0`
- MongoDB
- Redis 可选；启用缓存或分布式锁能力时需要配置

安装依赖：

```bash
pnpm install
```

锁文件 `pnpm-lock.yaml` 必须提交到仓库。CI 和服务器发布安装均使用 `--frozen-lockfile`，避免依赖版本在发布时漂移。

## 4. 环境变量

### 4.1 读取规则

应用启动时按 `NODE_ENV` 决定环境文件读取顺序：

- 非生产：`.env.local -> .env.dev -> .env`
- 生产：只读取 `.env`

本地开发通常复制 `.env.dev` 为 `.env.local` 后调整个人配置：

```powershell
Copy-Item .env.dev .env.local
```

生产环境变量不进入 Git 仓库，也不进入发布压缩包。GitHub Actions 自动发布时，服务器环境文件固定放在：

```text
/www/env/backend/.env
```

发布脚本会在每次 release 中复制该文件为当前版本目录下的 `.env`。

## 6. 索引同步

一次性同步索引：

```bash
pnpm db:indexes:sync
```

用途：

- 将当前 schema 定义的索引同步到已有数据库
- 补齐新增 partial index
- 清理已经移除的旧索引

启动时自动同步：

```env
MONGO_SYNC_INDEXES_ON_BOOT=true
```

说明：

- 默认关闭。
- 建议只在开发环境或维护窗口使用。
- 生产环境更推荐在维护窗口显式执行 `pnpm db:indexes:sync`。

## 7. 运行说明

### 7.1 API 基础前缀

- 默认：`http://localhost:3000/api/v1`

### 7.2 关键入口

- 首页主体：`GET /api/v1/home`
- 健康检查：`GET /api/v1/health`
- 精选推荐：`GET /api/v1/search/featured`
- 全文搜索：`GET /api/v1/search/fulltext`
- 快速搜索：`GET /api/v1/search/quick`
- 相关推荐：
  - `GET /api/v1/articles/:id/related`
  - `GET /api/v1/books/:id/related`
  - `GET /api/v1/topics/:id/related`
  - `GET /api/v1/images/:id/related`
- 管理员精选：`GET /api/v1/admin/featured-contents`
- 管理端内容治理：
  - `GET /api/v1/admin/content/summary`
  - `GET /api/v1/admin/content`
- 管理端 AI 编辑辅助：
  - `POST /api/v1/admin/ai/compose`
  - `POST /api/v1/admin/ai/compose/stream`

### 7.3 当前默认业务规则

- 四类内容提交后默认写入公开态与已审核态。
- 公开接口统一只返回可公开内容。
- 图包业务已移除 `width`、`height`。
- 书籍业务已移除旧字段 `hots`。
- 游戏业务已移除旧字段 `scheduleLabel`。
- AI 编辑辅助只返回建议，不直接写业务内容库。

## 9. 阿里云发布与 PM2

### 9.1 服务器环境

服务器需要准备：

- Node.js `>=20`
- pnpm `10.11.0`
- PM2
- MongoDB 连接能力
- Redis 连接能力，可选
- 可持久化的媒体目录，例如 `/var/lib/mononest/media`

首次部署前，服务器建议执行：

```bash
mkdir -p /www/apps/backend/shared /www/apps/backend/releases /www/env/backend /var/lib/mononest/media
corepack enable
corepack prepare pnpm@10.11.0 --activate
npm install -g pm2
```

然后创建并填写生产环境变量：

```bash
vi /www/env/backend/.env
```

### 9.2 服务器目录约定

- `/www/apps/backend/shared`：上传临时包
- `/www/apps/backend/releases/<git-sha>`：每次发布版本
- `/www/apps/backend/current`：当前运行版本软链
- `/www/env/backend/.env`：生产环境变量
- `/var/lib/mononest/media`：建议的媒体持久化目录

### 9.3 GitHub Actions 自动发布

工作流文件：

```text
.github/workflows/deploy-backend.yml
```

回滚工作流文件：

```text
.github/workflows/rollback-backend.yml
```

触发规则：

- 推送到 `main` 后自动构建并发布。
- CI 使用 Node.js `20` 和 pnpm `10.11.0`。
- CI 使用 `pnpm install --frozen-lockfile`。
- 发布包固定包含 `dist`、`package.json`、`pnpm-lock.yaml`、`ecosystem.config.cjs`。

GitHub Secrets：

- `SERVER_HOST`
- `SERVER_USER`
- `SERVER_PORT`
- `SERVER_SSH_KEY`

发布流程：

1. GitHub Actions checkout 源码。
2. 启用 Node.js `20` 和 pnpm `10.11.0`。
3. 使用锁文件安装依赖并执行 `pnpm build`。
4. 打包运行所需文件为 `backend.tar.gz`。
5. 上传到 `/www/apps/backend/shared`。
6. 在服务器解压到 `/www/apps/backend/releases/<git-sha>`。
7. 执行 `pnpm install --prod --frozen-lockfile`。
8. 从 `/www/env/backend/.env` 复制生产环境变量到当前 release。
9. 将 `/www/apps/backend/current` 指向当前 release。
10. 清理旧 PM2 进程名后执行 `pm2 start ecosystem.config.cjs --env production --update-env`。
11. 安装并配置 `pm2-logrotate`。
12. 执行 `pm2 save`。
13. 使用当前 `.env` 中的 `PORT` 和 `API_PREFIX` 生成健康检查地址，并 curl `GET /health`。
14. 健康检查通过后，仅保留最近 5 个 release。

### 9.4 PM2 配置

PM2 配置文件：

```text
ecosystem.config.cjs
```

当前固定事实：

- 服务名：`mononest-api`
- 运行入口：`dist/src/main.js`
- 运行模式：单进程 `fork`
- 生产环境：`NODE_ENV=production`
- 内存保护：`max_memory_restart=512M`

手动管理命令：

```bash
pnpm pm2:start
pnpm pm2:reload
pnpm pm2:logs
pnpm pm2:stop
```

配置开机自启：

```bash
pm2 startup
pm2 save
```

`pm2 startup` 会输出一条需要按服务器环境复制执行的系统命令，执行后再运行 `pm2 save`。

部署脚本会自动确保 `pm2-logrotate` 已安装，并设置：

- `max_size=20M`
- `retain=14`
- `compress=true`

手动安装或确认配置：

```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 20M
pm2 set pm2-logrotate:retain 14
pm2 set pm2-logrotate:compress true
pm2 save
```

### 9.5 GitHub Actions 回滚

GitHub Actions 支持通过 `workflow_dispatch` 手动触发回滚。回滚工作流合入默认分支后，进入 GitHub 仓库的 Actions 页面，选择 `Rollback MonoNest Backend`，输入 `release_id` 后运行即可。

`release_id` 通常是部署时的 git sha，对应服务器目录：

```text
/www/apps/backend/releases/<release_id>
```

回滚工作流会执行：

1. 校验 `release_id` 不包含路径穿越或空白字符。
2. 校验目标 release 目录存在。
3. 校验目标 release 中存在 `ecosystem.config.cjs` 和 `dist/src/main.js`。
4. 从 `/www/env/backend/.env` 复制生产环境变量到目标 release。
5. 将 `/www/apps/backend/current` 原子切换到目标 release。
6. 清理旧 PM2 进程名并启动 `mononest-api`。
7. 执行 `pm2 save`。

如果 release 已被自动清理，工作流会失败并输出最近可用的 release 列表。当前自动部署只保留最近 5 个 release。

### 9.6 服务器手动回滚

将 `current` 软链指向旧 release 后重新加载：

```bash
ln -sfn /www/apps/backend/releases/<old-sha> /www/apps/backend/current.next
mv -Tf /www/apps/backend/current.next /www/apps/backend/current
cd /www/apps/backend/current
pm2 delete mononest-api || true
pm2 start ecosystem.config.cjs --env production --update-env
pm2 save
```

## 10. 上线前检查

- `.env` 中 `NODE_ENV=production`。
- `CORS_ORIGINS` 只配置真实前端域名。
- `MONGO_URI` 指向生产数据库。
- `JWT_ACCESS_SECRET` 和 `JWT_REFRESH_SECRET` 不能使用示例值。
- `OPENAI_API_KEY` 已按实际启用情况配置。
- `MEDIA_STORAGE_ROOT` 指向服务器持久化目录。
- `MEDIA_IO_CONCURRENCY` 和 `MEDIA_IMAGE_PREVIEW_CONCURRENCY` 按服务器内存配置调整；图片批量上传异常时可先降到 `2` 和 `1`。
- Nginx 反向代理需要允许足够大的请求体，例如 `client_max_body_size 200m;`。
- 服务器安全组放行后端端口或反向代理端口。
- 若使用 OpenAI，确认服务器能访问 `OPENAI_BASE_URL`。
- 首次部署或 schema 变更后，维护窗口执行 `pnpm db:indexes:sync`。
- GitHub Secrets 已配置：`SERVER_HOST`、`SERVER_USER`、`SERVER_PORT`、`SERVER_SSH_KEY`。
- 健康检查可在服务器本机访问，例如默认配置为 `curl http://127.0.0.1:3000/api/v1/health`。
- PM2 已安装 `pm2-logrotate`，并能在 `pm2 list` 中看到 `pm2-logrotate`。

## 11. 常见排查

### 11.1 `pnpm` 不可用

```bash
corepack enable
corepack prepare pnpm@10.11.0 --activate
pnpm -v
```

### 11.2 依赖安装失败

优先检查：

- `pnpm-lock.yaml` 是否已提交。
- CI 和服务器 pnpm 版本是否为 `10.11.0`。
- 是否误改了 `package.json` 但没有同步更新锁文件。

### 11.3 Mongo 无法连接

优先检查：

- `MONGO_URI`
- `MONGO_DB_NAME`
- Mongo 服务或云数据库访问白名单

### 11.4 索引没有生效

优先检查：

- 是否执行过 `pnpm db:indexes:sync`
- 是否开启了 `MONGO_SYNC_INDEXES_ON_BOOT`
- 数据库里是否残留旧索引

### 11.5 媒体上传失败

优先检查：

- 媒体大小限制
- 上传字段名是否正确
- `MEDIA_STORAGE_ROOT` 是否可写
- 当前 release 目录下 `.tmp-uploads` 是否可写；多图上传会先落临时文件，再按并发读取处理
- Nginx `client_max_body_size` 是否小于本次批量上传总大小
- `MEDIA_IO_CONCURRENCY` 和 `MEDIA_IMAGE_PREVIEW_CONCURRENCY` 是否过高导致内存压力
- PM2 运行用户是否有媒体目录读写权限
- `pm2 logs mononest-api --lines 100` 是否出现 `max_memory_restart` 或进程重启记录

### 11.6 PM2 服务未更新

优先检查：

- `/www/apps/backend/current` 是否指向最新 release。
- `ecosystem.config.cjs` 是否随发布包上传。
- 是否执行了 `pm2 start ecosystem.config.cjs --env production --update-env`。
- `pm2 logs mononest-api` 中是否存在启动异常。

### 11.7 健康检查失败

优先检查：

- `pm2 list` 中 `mononest-api` 是否在线。
- `.env` 中 `PORT` 和 `API_PREFIX` 是否与 curl 地址一致。
- 本机是否能访问默认健康检查地址：`curl http://127.0.0.1:3000/api/v1/health`。
- `pm2 logs mononest-api --lines 100` 是否存在启动异常。

### 11.8 PM2 日志切割未生效

优先检查：

- `pm2 list` 中是否存在 `pm2-logrotate`。
- `pm2 conf pm2-logrotate` 中 `max_size`、`retain`、`compress` 是否符合预期。
- 服务器是否允许从 npm 安装 PM2 module。

### 11.9 AI 接口不可用

优先检查：

- `OPENAI_API_KEY`
- `OPENAI_MODEL_ADMIN_COMPOSE`
- `AI_ADMIN_STREAM_ENABLED`
- OpenAI 上游网络是否可达
- 调用用户是否已登录
