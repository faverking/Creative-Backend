# 业务与架构设计说明

## 1. 文档定位

本文件是当前后端的主设计文档，合并说明三类信息：

- 业务对象和稳定业务规则
- 模块边界和接口分层

如果只需要接口字段和路径，优先看 [API接口与参数说明](./API接口与参数说明.md)。  
如果只需要启动、目录和环境变量，优先看 [工程目录与运行指南](./工程目录与运行指南.md)。  
仓库约束基线以 [spec.md](./spec.md) 为准。

## 2. 设计目标

`MonoNest` 当前的核心目标有三件事：

- 保持模块边界清晰，避免为未来场景过度抽象
- 保持业务语义、可见性、关系与计数口径一致
- 提供稳定、可被 `MonoApp` 直接消费的 API 契约

## 3. 业务对象与主线

### 3.1 面向的消费方

当前主要服务两类消费方：

- `portal-web` 或其他公开读取侧
- `admin-web` 管理与编辑侧

系统当前主线是：

- 管理和展示四类核心内容
- 为内容提供评论、收藏、通知、历史等互动能力
- 提供首页聚合、精选、搜索与相关推荐
- 为后台编辑提供内容治理工具

### 3.2 四类核心内容

`articles`

- 定位：情报、资讯、动态、公告、专题导读
- 典型字段：`title` `desc/summary` `content` `themeId` `images`

`topics`

- 定位：游戏内容、资源整理、版本更新、作品浏览
- 典型字段：`topicId` `typeId` `title` `desc/summary` `content` `featureFlags` `downloadUrl` `images`

`books`

- 定位：漫画、小说、资料等书库型内容
- 典型字段：`name/title` `cover` `desc/summary` `author` `part` `area` `style` `chapterList`

`images`

- 定位：图片集合、壁纸、插画、CG 等资源型内容
- 典型字段：`title` `desc/summary` `images` `cover` `themeId` `source`

### 3.3 四类内容的统一语义

四类内容统一具有这些公共概念：

- `reviewStatus`
- `visibility`
- `viewCount`
- `favorCount`
- `replyCount`

当前默认规则：

- 新提交内容默认进入 `approved + public`
- 公开接口统一只返回可公开内容
- 详情访问会累加 `view_count`

公开可见口径：

- `articles`：`published + approved + public + not deleted`
- `books / topics / images`：`approved + public`

### 3.4 内容生命周期

当前内容生命周期可以简化理解为：

1. 用户或编辑创建内容
2. 内容默认进入公开且已审核状态
3. 公开详情访问累加浏览量
4. 内容参与首页、搜索、精选和相关推荐
5. 后台可执行设私密、精选取消或永久删除

治理链路需要同时考虑：

- 收藏关系
- 评论关系
- 消息通知
- 浏览历史
- 精选配置
- 计数与可见性一致性

## 4. 配套业务规则

`comments`

- 根评论分页
- 回复单独拉取
- 内容详情上的 `replyCount` 表示总讨论量

`favorites`

- 统一使用 `POST /favorites/toggle`
- 收藏关系变化后同步回写目标内容 `favorCount`

`drafts`

- 草稿是私有业务
- 不参与公开搜索、公开统计、首页聚合、精选推荐

`notification`

- 当前主要围绕 `comment` 和 `reply`
- 返回的是可读、可跳转、可定位的通知读模型

`history`

- 是最近访问模型，不是完整行为审计流水
- 用于个人最近浏览展示

`featured-contents`

- 由后台配置精选
- 前台消费的是精选结果，不是配置表原始结构

## 5. 首页、搜索与精选

### 5.1 首页

`/home` 当前只负责首页主体聚合，返回：

- `articleSection`
- `columnSection`
- `bookshelfSection`
- `gallerySection`
- `generatedAt`

当前不再承担：

- 快捷入口
- 顶层精选块
- 统计块

### 5.2 搜索

当前搜索分三类：

- `quick`：标题前缀匹配
- `fulltext`：Mongo text index
- `featured`：管理员精选优先，热度补位

此外四类内容详情页都有 `/:id/related` 用于相关推荐。

## 6. 模块边界与接口分层

### 6.1 当前业务域

- `articles`：情报
- `topics`：游戏
- `books`：书库
- `images`：图包
- `comments`：评论与回复
- `favorites`：收藏关系
- `drafts`：草稿
- `notification`：消息通知
- `history`：浏览历史
- `featured-contents`：精选配置
- `admin/content`：内容治理与汇总视图
- `admin/featured-contents`：后台精选配置

### 6.2 主分层

当前代码主分层仍然是：

`controller -> service/application -> repository -> schema`

职责边界：

- `controller`：路由、鉴权、DTO 校验、参数拆解
- `service/application`：业务编排、事务边界、副作用协调、结果映射
- `repository`：数据访问
- `schema`：集合结构和索引定义

### 6.3 横切能力

- `common/`：守卫、装饰器、拦截器、公共常量与工具
- `infra/`：数据库、日志、Redis、存储、审计等基础设施
- `workspace/`：跨内容摘要、关系清理、访问记录等内部能力
- `search/`：全文搜索、精选、相关推荐

`workspace/` 是内部跨域能力，不单独暴露独立 HTTP 控制器。

### 6.4 接口分层

公共消费接口：

- `GET /home`
- `GET /search`
- `GET /search/fulltext`
- `GET /search/quick`
- `GET /search/featured`
- 四类内容公开列表与详情
- 四类内容相关推荐
- 评论读取
- 公开媒体读取与下载

登录用户接口：

- `/auth/*`
- `/users/me*`
- `/drafts/*`
- `/favorites/me`
- `/notifications/*`
- `/history/me`
- 四类内容的 `me` 列表与编辑接口
- 评论创建与回复
- 媒体上传

管理端接口：

- `/admin/ping`
- `/admin/featured-contents/*`
- `/admin/content/*`

## 7. 当前稳定事实

### 7.1 内容字典以后端为准

内容分类与标签字典目前稳定存在于：

- `ARTICLE_THEME_LABELS`
- `IMAGE_THEME_LABELS`
- `BOOK_PART_LABELS`
- `BOOK_AREA_LABELS`
- `BOOK_STYLE_LABELS`
- `TOPIC_LABELS`
- `TOPIC_TYPE_LABELS`
- `TOPIC_FEATURE_FLAG_LABELS`

前后端如果需要相同枚举语义，优先对齐这些字典，不要自行扩写一套临时文案。

### 7.2 已移除的旧字段

- 图包：`width`、`height`
- 书籍：`hots`
- 游戏：`scheduleLabel`

前端不需要再兼容这些历史字段。

### 7.3 媒体相关

- 图片支持上传、预览、详情、下载、批量打包
- ZIP 上传支持 `extract` 与 `direct`
- ZIP 下载支持 `package` 与 `direct`
- `preview` 与 `download` 的 HTTP 行为不同，前端接入时不要混用
